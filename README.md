Нативное SwiftUI-приложение и WidgetKit-виджет для локальной Git-активности на macOS.

## Возможности

- несколько независимых календарей по папкам;
- рекурсивный поиск вложенных Git-репозиториев;
- явный фильтр коммитов по имени или email автора без чтения глобального Git-профиля;
- календарь с интенсивностью цвета по числу коммитов;
- просмотр коммитов, diff-статистики и причин риска за выбранный день;
- недельная частота коммитов;
- отдельная сводка текущего месяца и помесячная динамика proxy-метрик;
- локальные прокси BCE/day, ACE и Aberrant BCE;
- отдельный настраиваемый виджет для каждого календаря;
- серая календарная сетка в виджете появляется сразу после добавления папки, не дожидаясь завершения сканирования;
- Git-история и diff-статистика остаются локальными; приложение передаёт виджету только компактные JSON-снимки через App Group, токены GitHub/GitLab не нужны;
- проверка новых версий через публичные GitHub Releases при запуске.

При первом запуске приложение не добавляет папки автоматически. Каждый календарь создаётся пользователем через системную панель выбора папки.

Период общей статистики начинается с самого раннего коммита, который соответствует настроенному фильтру автора, и заканчивается текущим днём. Поэтому дни до начала работы не ухудшают показатели.

## Метрики

Показатели намеренно называются **proxy**: формулы BlueOptima проприетарны, поэтому приложение не может воспроизвести официальный расчёт.

- `BCE/day proxy` — сумма логарифмических весов содержательных изменений на будний день. Вес учитывает изменённые строки, число исходных файлов и наличие тестов; дневное значение ограничено, чтобы частые мелкие коммиты не раздували показатель.
- `ACE proxy` — нормированный индекс 0–100 на основе среднего веса активного дня.
- `Aberrant proxy` — доля содержательных строк, взвешенная по проверяемым рискам: крупное изменение, широкая поверхность изменения и существенный production diff без сопутствующих тестов.

Сгенерированные файлы, vendor, Pods, node_modules и binary-файлы исключаются. Пороги риска меняются отдельно для каждого календаря.

Эти показатели предназначены для наблюдения за тенденцией и поиска конкретных коммитов для ревью. Они не должны использоваться для искусственного дробления коммитов или подмены инженерного качества.

## Запуск

1. Открыть `GitCalendar.xcodeproj` в Xcode.
2. Выбрать свою Development Team для целей `GitCalendar` и `GitCalendarWidget`, если Xcode попросит.
3. Запустить схему `GitCalendar`.
4. После первого сканирования добавить `Git Calendar` через стандартное меню виджетов macOS.
5. В настройках виджета выбрать нужный календарь.

## Как добавить виджет

1. Один раз запустить подписанное приложение из Xcode или перенести `Git Calendar.app` из DMG в `/Applications` и открыть его.
2. Нажать правой кнопкой по рабочему столу и выбрать **Изменить виджеты**.
3. Найти **Git Calendar** и перетащить виджет нужного размера на рабочий стол.
4. Нажать правой кнопкой по виджету → **Изменить Git Calendar** → выбрать календарь папки.

WidgetKit использует App Group, поэтому локальная сборка должна быть подписана одной Development Team для обеих целей: `GitCalendar` и `GitCalendarWidget`.

Готовые сборки публикуются в [GitHub Releases](https://github.com/malinatrash/git-calendar/releases/latest). В CI они подписываются ad-hoc; до появления Developer ID и notarization при первом запуске может потребоваться выбрать **Open** в контекстном меню приложения.

Для App Group используется `group.io.github.malinatrash.GitCalendar`. При смене bundle identifier нужно одинаково изменить группу в entitlements и `SharedConstants.appGroup`.

## Проверка

```sh
./scripts/build.sh
```

Скрипт собирает приложение и виджет, затем запускает unit-тесты без code signing.

## CI/CD и обновления

GitHub Actions собирает arm64-приложение на `macos-26`, запускает тесты и прикладывает DMG как artifact к каждому push. Тег вида `v1.0.0` дополнительно создаёт GitHub Release с DMG.

Приложение при запуске запрашивает `releases/latest` репозитория `malinatrash/git-calendar`. Если версия новее `CFBundleShortVersionString`, оно предлагает скачать DMG из release assets.

Сейчас CI использует ad-hoc подпись. Для распространения без предупреждения Gatekeeper потребуется добавить Developer ID signing и notarization credentials в GitHub Secrets.

Если в локальной сборке общий App Group недоступен, приложение показывает предупреждение вместо молчаливого сохранения данных в другое хранилище. Для запуска из Xcode выберите один и тот же Development Team для приложения и Widget Extension; macOS-style идентификатор группы формируется из `$(AppIdentifierPrefix)` во время подписи.
